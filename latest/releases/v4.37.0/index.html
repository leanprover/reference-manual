Lean 4.37.0-rc1 (2026-11-18)🔗

Warning

These release notes describe a release candidate, not the final release. They may be incomplete and are subject to change.

For this release, 370 changes landed. In addition to the 71 feature additions and 159 fixes listed below, there were 7 refactoring changes, 1 documentation improvement, 108 performance improvements, 4 improvements to the test suite, and 20 other changes.

Language🔗

  • #16533 changes registerReservedNamePredicate to take two functions: a test on the last component of the name, and the predicate itself. A name is a candidate for being reserved only if its last component passes the test.

  • #16531 fixes an "environment already contains" import error when two modules realize the same match congruence equation.

  • #16512 fixes a bug wherein loose bvars where not always checked for in inductive declarations. This issue looks benign, and does not lead to an apparent proof of false.

  • #16519 makes the generation of match equations faster for a match with many alternatives and a catch-all. The big_match_string benchmark with 128 alternatives is about 14% faster (#16313).

  • #16505 makes each congruence equation f.match_1.congr_eq_i of a match be generated on demand, independently of the other ones. It fixes a performance regression from #16502 for a match with many alternatives where only a few match equations are not proved by rfl, for example literals or constructors followed by a catch-all: big_match_nat_split and big_match_partial are 18% and 7% faster. Referring to f.match_1.congr_eq_i by name also generates only that theorem.

  • #16503 makes the kernel type check a constant created by a nested realization only once. For example, the equation theorems of a function request the equations of its match, and the kernel checked each of those theorems twice, or three times when they requested further theorems themselves. Generating the equations of a String → Nat function with 128 literal alternatives is about 25% faster. It also fixes repeated error messages: a kernel error in such a constant was reported once per nesting level, and is now reported once.

  • #16501 adds the option shiftLeft.threshold (default: 65536). whnf, simp, and grind no longer evaluate a left shift of literals when the shift amount is above this threshold, and report a warning instead, as they already do for exponents above exponentiation.threshold. Previously, a shift amount of 2^32 or more aborted the Lean process with INTERNAL PANIC: Nat.shiftl exponent is too big, e.g., in example : (1 <<< 4294967296 : Nat) = 0 := by simp. cbv and the compiler use the same bound as a constant.

  • #16404 makes the do elaborator reject a finally block that reassigns a mut variable in scope at the try. The error names the reassigned variables:

    A `finally` block cannot reassign the `mut` variable `s`.

  • #16482 turns the csimpCore test, which checks that declarations replaced by csimp are noncomputable, into a linter.

  • #16480 makes equation theorems of nonrecursive definitions faster to type check when the definition is a match on literals. For a String → Nat function with 128 String literal alternatives, generating its equation theorems, which simp [f] and cbv need, takes 15.5s instead of 25.7s.

  • #15856 adds an optional starting position to Lean.Parser.parseHeader, allowing tools such as Verso to parse module headers inside a larger source file while preserving source locations.

  • #16477 makes generating the equations of a match faster when a discriminant is annotated with h : and the patterns are values. For match h : s with and 64 String literal alternatives, it takes 0.40s instead of 1.50s.

  • #16476 makes the proofs that two String literals are different cheaper to check, improving on #16474. For two literals that share a prefix of 512 characters, the kernel checks the proof in 3.5ms instead of 4.4ms.

  • #16474 makes the proofs that two String literals are different faster to build and to check. These proofs are used by simp, cbv, and the equations of match expressions with String patterns. For two literals that share a prefix of 64 characters, the kernel checks the proof in 0.60ms instead of 1.85ms.

  • #16465 makes generating the equations of a match with many value patterns faster. For a match with two discriminants and 64 alternatives such as | "name", 0 => .. followed by a catch-all, it takes 0.38s instead of 1.16s.

  • #16460 makes generating the equations of a match with many alternatives faster when the patterns contain literals nested in constructors, e.g., | some "a" => ... For 32 alternatives of this form, generating the match equations takes 0.53s instead of 1.45s.

  • #16354 speeds up the generation of equation lemmas for definitions that match on String literals. With 64 literal patterns, generation used to hit the heartbeat limit.

  • #16408 makes elaborating large mutual blocks defined by well-founded recursion faster. Cleaning up the termination proof goals no longer takes time proportional to the number of functions in the block, which used to make elaborating the whole block quadratic. As a side effect, the functional induction principle of a function with a nested recursive call, such as f (f x), no longer contains a duplicate induction hypothesis for the inner call; proofs that name the hypotheses of such a case positionally need to drop one name.

  • #16422 simplifies the result type of the function that packs a mutual block defined by well-founded recursion: where both branches of a case split on the packed argument have the same non-dependent result type, the case split is omitted. If all functions have the same result type, the packed function now has that type, as the docstring of ArgsPacker.Mutual.uncurryType already promised. Previously this type was a case split over all functions of the block, which appeared in the motive of every case split in the definition and its unfolding lemma and made type checking large blocks slow.

  • #16409 packs the arguments of a mutual block defined by well-founded recursion into a balanced tree of PSum types instead of a right-nested chain. The nesting depth of packed arguments and of the case splits that take them apart becomes logarithmic in the number of functions, which makes elaborating and type checking large blocks much cheaper. Blocks of up to three functions are packed as before.

  • #16320 fixes a segfault when withImportModules is called a second time in one process and the imported module imports another package root, a regression from #15291.

  • #16279 fixes Expr.hasLooseBVar, Expr.liftLooseBVars, Expr.lowerLooseBVars, task priorities and the kernel's handling of the number of parameters of an inductive declaration, which silently truncated values of 2^32 and above to 32 bits. For example, the kernel accepted an inductive declaration with numParams := 2^32 and recorded numParams = 0, and a task with priority 2^32 - 1 ran synchronously in the caller rather than on a dedicated thread.

  • #15889 makes type class resolution reuse cached results much more often. A result is shared by all local contexts that agree on the local instances of the classes its search consulted, and declaring or erasing an instance only invalidates the results whose search consulted the instance's class. Building all of Mathlib takes about 2.7% less wall-clock time, and about 6.7% less time in type class resolution.

  • #16273 makes set_option maxRecDepth 0 mean "no limit" in the compiler and in macro expansion, and makes huge maxRecDepth values act as unlimited in the kernel instead of wrapping around to a small limit. Previously, maxRecDepth 0 was stricter than e.g. maxRecDepth 10000, and values such as 2^60 could reject shallow declarations.

  • #16235 makes the equation lemmas f.eq_<i> keep the haves and lets of the right-hand side when they split a match below them, instead of inlining their values into each equation. Inlining duplicated the values, exponentially for nested haves, and lost the sharing of the join points that do notation introduces, which vcgen +jp [f] needs (#16122). The generated equations are otherwise the same: inlining the haves gives back the previous equations.

  • #16252 fixes a kernel error unknown constant 'f.match_1.eq_1' when generating equation lemmas whose statements contain cast proofs, as happens when a match on a literal is reduced under a dependent argument. Definitions whose body eliminates an empty type now get one equation lemma stating the unfolded definition, instead of none.

  • #16219 fixes timeouts when comparing distinct Float/Float32 literals, for example while generating the equation lemmas of a match on float literals. Unifying such literals used to unfold the float model on both sides in lockstep.

  • #16215 fixes match on Float and Float32 literal patterns treating literals that denote the same value (such as 5 and 5.0, or 16777216 and 16777217 as Float32) as different patterns, which could cause a matching alternative to be skipped. Such overlapping alternatives are now also reported as redundant.

  • #16208 makes the equation lemmas f.eq_<i> keep the haves and lets at the root of the right-hand side, unless they must be zeta-reduced to split a match. For a definition without a match, f.eq_1 is now the same as f.eq_def.

  • #16138 makes Kernel.Environment.replay add the constants used in the types of all members of a mutual inductive block before adding the block. Previously only the dependencies of the member through which replay reached the block, and those of the constructors, were added, so a valid export could be rejected with unknown constant, depending on hash order.

  • #16132 speeds up type class resolution for classes with many instances.

  • #16105 ports the macro used for long list to a term elaborator instead. The term elaborator mimicks the logic of the previous macro but executes it noticeably faster than before.

  • #16091 avoids using an mvar for the type of a numlit when the type is known.

  • #16078 improves the performance of elaborating long list literals.

  • #16047 fixes equation lemmas of structurally recursive functions whose rfl proof was very expensive for the kernel to check. For example, generating f.eq_2 for the following definition failed with kernel deep recursion, and cbv, rw [f.eq_2], and simp [f] failed with it:

    def f : Nat → Nat → Nat
  | 0, x => x
  | n+1, x => f n ((x * 1103515245) % 5)

  • #16046 fixes quadratic elaboration behavior for large string-literal equalities such as theorem t : s = String.ofList l := rfl.

  • #15959 changes the parser of return to allow the term after return to start on a later line.

  • #15968 speeds up Environment.hasUnsafe, which mkAuxTheorem runs on the type and value of every auxiliary theorem, such as each proof produced by grind. Imported constants are now read from the imported constant map, which is computed once per traversal. Before, findAsync? wrapped each of them in an AsyncConstantInfo, allocating the wrapper, two Tasks and a ConstantVal.

  • #15955 adds the @[vcgen_simp] attribute, which collects Sym.simp theorems for the vcgen tactic.

  • #15951 makes normalization for the TC cache fail if a local instance is not a free variable.

  • #15855 adds a mkInstanceNameOfType for determining the fully qualified name of an instance and makes delta deriving use it.

  • #15898 makes @[deprecated] on syntax, macro, elab, notation and the mixfix commands deprecate the declared syntax, like deprecated_syntax.

  • #15942 speeds up lookups of attribute and environment-extension data for imported declarations, such as reducibility status, tag attributes, parametric attributes and MapDeclarationExtension.find?. These lookups run very frequently during elaboration, and their results are unchanged.

  • #15921 speeds up Expr.consumeTypeAnnotations, which the elaborator calls on the expected type of each application argument.

  • #15920 speeds up Expr.cleanupAnnotations, which match_expr and let_expr call on the discriminant and after every argument they peel.

  • #15897 ensures that the rules for macros which are deprecated are themselves not linted for deprecated declarations.

  • #15806 allows users of the deprecated_syntax command to optionally specify a syntax transformation to produce a suggested replacement that will then be available as a code action.

  • #15879 makes notations, macros and other checked quotations (``(…)) report deprecated constants where they are defined, in addition to every place they are used.

  • #15858 changes many places that erase free variables from the local instances to use the same functions, LocalInstance.erase and LocalInstance.eraseAll (a new function), and makes them not rely on the fact that fvar is a free variable. Local instances which are not free variables are useful e.g. for the new deriving framework (#15320) but should not be used in code that may revert or clear free variables.

  • #15863 makes the elaboration of terms with many postponed type class problems, such as long arithmetic expressions over numerals, take linear instead of quadratic time. For example, def bla : Nat := 2 ^ 3 * 8 + 2 ^ 3 * 8 + ... with 80 summands now spends 65 ms in type class inference instead of 2.95 s.

  • #15824 fixes dsimp and simp unfolding a function defined by mutual structural recursion when a match around a recursive call to another function of the group does not reduce. The resulting proof was accepted by the elaborator but rejected by the kernel.

  • #15737 fixes fun_cases and fun_induction for a match whose discriminant appears in the type of another variable in the goal.

  • #15813 makes the "deprecated syntax" linter report in places it previously missed.

  • #15371 expands the condition for which the major of a recursor can be eta-expanded. Namely, subsingleton structures such as And should be eta-expanded in this situation.

  • #15103 ensures is_def_eq_proof_irrel runs before reducing any potential proofs in is_def_eq_core rather than after. This is already the order in which things run in the elaborator, so no need for any changes there.

  • #15373 eta-expands partial constructor applications.

  • #15682 fixes mkBindUnlessPure to only run the continuation once, making sure that using pure () doesn't elaborate everything afterwards twice.

  • #15740 makes name resolution treat auxiliary local declarations (recursive references to the definition being elaborated, let rec and where) like the global declarations they represent, for both more consistent semantics and faster lookups.

  • #15738 fixes a (kernel) unknown constant error for structurally recursive definitions where a recursive call appears as a match discriminant and an alternative of that match also recurses. Such definitions are now compiled using structural recursion.

  • #15318 adds a getEntriesWithKeys function to DiscrTree that can be used to get all entries inside of a DiscrTree that have a specific key sequence.

  • #15710 fixes the functional induction and cases principles for functions that match with a named pattern on a literal or a constructor without arguments (e.g. n@5 or b@true), which were previously rejected by the kernel.

Library🔗

  • #16487 bakes monotonicity into Lean.Order.PredTrans. PredTrans.mk f h builds a transformer from a function f and a proof h that f is monotone, PredTrans.apply applies it, and PredTrans.apply_mono states its monotonicity. The WP class now carries only trans since monotonicity is baked in.

  • #16497 fixes the bad performance on Std.Http.Header.Name.ofString? and Header.Value.ofString?.

  • #16417 fixes twelve cases where the HTTP/1.1 client, the server or the URI printer did not follow RFC 9110, RFC 9112 or RFC 3986.

  • #16418 reimplements IO.Process.spawn and the operations on IO.Process.Child. This fixes a number of bugs on all platforms, makes spawning much faster in processes that use a lot of memory, and makes spawn throw an error if the command cannot be started.

  • #16441 makes all functions that later receive a csimp lemma noncomputable, to ensure that the slow versions are never used.

  • #16429 makes the Std.Http server keep reading a client's upload before closing the connection when it rejects the request from its head alone, such as a 413 for a declared body over maxBodySize or a 400 for conflicting Content-Length fields. Previously the client could get a connection reset while still sending its body, and lose the response.

  • #16426 makes closing a TCP socket on Windows cancel all pending writes, whichever thread issued them, as it already does on other platforms. Before this, a write to a peer that does not read could keep the socket open indefinitely if a different thread had issued it.

  • #16400 fixes several Std.Http bugs:

    • A 2xx response to CONNECT has no framing fields or content and closes the connection.

    • close in Connection wins over keep-alive for every HTTP version, and empty list elements are accepted.

    • HTTP/1.0 requests are sent with Content-Length, and an HTTP/1.0 response with a transfer coding becomes a 500.

    • Request-target limits derive from maxUriLength, an overlong request line gets 414, and trailing CRLF at EOF is not a second request.

    • Chunk extensions with obs-text are ignored instead of failing the request, and leading zeros don't count toward the chunk-size limit.

    • URI.Config defaults are raised, and padded ports and 253-character hosts with a trailing dot parse.

    • : in a username is encoded, and a RequestTarget drops userinfo and the fragment.

    • Status.isServerError covers 600–999.

    • waitShutdown wakes every waiter, and reads stop at maximumRecvSize while a response streams.

    • The server lingers after an early response, a failing onFailure no longer skips cleanup, and late response bodies are closed.

    • Body.Stream.close keeps accepted bytes, and a cancelled readAll throws. AI Assisted (Claude)

  • #16366 adds Std.Async.Watchdog, which enforces deadlines on a sequence of waits with a single background timer and cancels a CancellationContext with .deadline when a wait outlives its deadline.

  • #16380 makes the HTTP/1.1 server report truncated request bodies to handlers and end connections whose peer stops reading. It adds Config.writeTimeout (default 30 seconds) and close on TCP sockets.

  • #16373 fixes the HTTP/1.1 server closing a keep-alive connection right after a slow response write finishes.

  • #16372 fixes the Substring.Raw.splitOn function which did not properly backtrack.

  • #16371 fixes a number of typos and factual errors in the docstrings for String functions.

  • #16362 makes an HTTP/1.0 request gets an HTTP/1.1 status line, a 205 response carries no content, the error responses the server writes itself carry a Date field and a short text/plain explanation, and a request with an unrecognized method or with a transfer coding other than chunked gets 501 instead of 400 or reaching the handler still coded.

  • #16360 revamps input and output handling for processes as seen in Process.output and Process.run.

  • #16328 fixes how Std.Http parses and prints URIs, request targets and Host values, and how decideRedirect resolves and follows redirects. Query values may contain =, a Location: / redirect goes to the root, and a printed URI reads back as the same URI. decideRedirect no longer takes the onlySafeRedirects and responseVersion parameters.

  • #16322 makes the HTTP/1.1 server continue with the next request while a response is still being written, instead of waiting for each socket write, which makes pipelined and keep-alive requests about 15–30% faster.

  • #16358 makes Process.Child.kill send SIGTERM or SIGKILL depending on a new parameter force defaulting to true (i.e. SIGKILL).

  • #15532 marks Dyadic.toRat as a coercion, and tags various lemmas with norm_cast.

  • #16282 fixes HTTP/1.1 message parsing, framing and connection handling in the client and server, and a few small Std.Http API issues.

  • #16080 makes Std.Http's HTTP/1.1 server answer a request whose request-target exceeds maxUriLength with 414 URI Too Long however the request line is split into reads. A read that ended between byte maxStartLineLength and the parser's maxUriLength check gave 400 Bad Request.

  • #15841 makes Std.Http's HTTP/1.1 parser wait for more input, instead of failing the message, when a read ends inside a chunk extension or a trailer field.

  • #16258 fixes many cases where Std.Time could not parse the text it formatted with the same pattern, including aaaa (#16247) and B at night (#16248). It also makes PlainDate.format and PlainDateTime.format use their locale argument, keeps non-zero seconds in zone offsets, and corrects Month.Ordinal.toDays and PlainDate.ofWallTime before 1970.

  • #16266 makes building and editing Std.Http.Headers several times faster by keeping header entries in an array that lookups scan.

  • #16079 makes Std.Http's URI and Host parsers read a host name that begins with an IPv4 address, such as 1.2.3.4-x.example, as a name, instead of rejecting it.

  • #16265 changes the encoding of HTTP structures to raw ByteArrays.

  • #15892 makes the String-keyed URI.Query operations (get, getD, find?, findAll, contains, erase and set) find a query parameter by its decoded name, so a parameter is found whichever valid percent-encoding it arrived in. Previously, a name a browser percent-encoded, such as a%3Ab for a form field named a:b, could not be looked up as "a:b", and set added a duplicate parameter instead of replacing it.

  • #15254 preserves literal + characters in HTTP query keys and values by encoding them as %2B, so they remain distinct from spaces. For a query received as a+b=1, get "a+b" now returns none; use get "a b" for that space-containing name, or send a%2Bb to represent a literal plus.

  • #15323 adds withIsExclusive a k h, which runs k on whether a is exclusive at runtime and is logically k false; the proof h : k true = k false keeps it sound. It lets safe code take different paths depending on sharing, for example to skip caching values that are referenced from at most one (owning) location.

  • #16225 makes Core.transform preserve sharing of unchanged application nodes. Other expressions already remained shared before.

  • #16217 adds wf_preprocess lemmas for the various higher-order Option functions.

  • #15269 speeds up leading- and trailing-zero counting on bitvectors, including kernel reduction, while preserving support in bv_decide. Proofs that unfold these operations should instead use BitVec.clz_eq_clzAuxRec or BitVec.ctz_eq_reverse_clz to recover their previous definitions.

  • #15265 adds Nat.trailingZeros and makes trailing-zero counting for Nat and Int efficient for arbitrary-precision values, speeding up dyadic normalization. Both operations return zero on zero, and Int.trailingZeros agrees with the natural-number operation on natAbs.

  • #16116 adds Vector.modify to update an element with a function, returning the vector unchanged when the index is out of bounds.

  • #16119 fixes GenericFormat.parse for patterns that rejected or misread what GenericFormat.format writes with the same pattern, and adds * and / by Nat and Int scalars to the Std.Time unit offsets and Duration. O and OOOO now accept a bare GMT, xxxxx accepts offsets without seconds, and Z, ZZ and ZZZ accept offsets with seconds. PlainTime.toTime12Hour no longer writes an hour that is off by one, such as 04:00:00 PM for 15:00.k, K and y with a BC era now parse to the correct hour or year instead of silently returning a wrong value.

  • #15997 makes JsonNumber.toString write a zero mantissa as 0 whatever the exponent. With an exponent above 10 it wrote 0.e-k, which is not JSON, so Json.compress output for such a number did not read back with Json.parse.

  • #15996 makes Json.parse fail with a parse error on arrays and objects nested more than 10,000 levels deep, instead of overflowing the stack and aborting the process.

  • #16113 makes kernel reduction of String.toList on a string literal take time linear in its length. Previously, decide +kernel on s.toList.length = 400 took about 8 s, and literals of a few thousand characters hit the kernel's recursion limit.

  • #15160 adds Nat.extendedGcd, returning a gcd and signed Bézout coefficients together with correctness and simplification lemmas.

  • #15077 adds UInt64.mulMod, UInt64.powMod, and UInt64.invMod? for fixed-width modular arithmetic without overflowing intermediate products. powMod accepts an arbitrary Nat exponent, and invMod? returns none for a zero modulus or noncoprime inputs.

  • #15885 adds IO.FS.renameIfNew which performs an atomic rename and errors if the destination already exists.

  • #16099 removes the instances instInhabitedForall and instInhabitedForallOfMonad.

  • #16095 introduces Lean.UnionFind as a compiler internal union find data structure. It features rank-based merging, path splitting, and efficient tracking of equivalence class members via cyclic pointers.

  • #16053 adds benchmarks for many parts of Std.HTTP, from encoding, body streams, handlers, and the H1 machine to server and client behavior over TCP.

  • #16022 speeds up Json.compress, Json.pretty and Json.escape on strings that contain non-ASCII characters, with unchanged output.

  • #15952 adds the missing order instances for Char, namely Min/Max and the associated lawfulness properties.

  • #15936 ensures that CXXFLAGS is passed to CaDiCaL's kitten component. This is necessary since the CaDiCaL 3.0 upgrade as it now includes kitten, a subsolver written in C.

  • #15653 fixes several libuv-backed system and network functions:

    • osGetPriority, osSetPriority, osGetGroup and getGroup throw IO.Error.invalidArgument for a process or group id that does not fit the operating system's id type, instead of truncating it and acting on a different process or group. osGetGroup now takes a Nat instead of a UInt64.

    • osGetGroup throws IO.Error.unsupportedOperation on Windows for every id.

    • osGetPasswd decides whether the group id is missing from the group id itself rather than from the user id.

    • IPv6 addresses are converted correctly on big-endian hosts.

    • IPv6Addr.ofString rejects a % zone suffix instead of silently dropping it.

    • getProcessTitle returns titles of 512 bytes or more, and fails with ENOBUFS instead of exhausting memory when the process arguments were never set up, as in the lean binary.

    • osGetenv returns none for a name with an = after its first character instead of the value of the variable named by its prefix. Windows variables such as =C: are still found.

    • IO.Process.Child.pid no longer leaks the Child object.

    • The libuv runtime sources no longer use using namespace std in headers, give their file-local helpers internal linkage, and declare the timer functions on all builds.

  • #15294 adds union/intersection emptiness distributivity lemmas:

    -- isEmpty_union_inter / isEmpty_inter_union
((m₁ ∪ m₂) ∩ m₃).isEmpty = ((m₁ ∩ m₃).isEmpty && (m₂ ∩ m₃).isEmpty)
(m₁ ∩ (m₂ ∪ m₃)).isEmpty = ((m₁ ∩ m₂).isEmpty && (m₁ ∩ m₃).isEmpty)

-- union_inter_equiv_empty_iff / inter_union_equiv_empty_iff
((m₁ ∪ m₂) ∩ m₃) ~m ∅ ↔ (m₁ ∩ m₃) ~m ∅ ∧ (m₂ ∩ m₃) ~m ∅
(m₁ ∩ (m₂ ∪ m₃)) ~m ∅ ↔ (m₁ ∩ m₂) ~m ∅ ∧ (m₁ ∩ m₃) ~m ∅

-- union_inter_eq_empty_iff / inter_union_eq_empty_iff (extensional variants)
(m₁ ∪ m₂) ∩ m₃ = ∅ ↔ m₁ ∩ m₃ = ∅ ∧ m₂ ∩ m₃ = ∅
